# 本地 MySQL 存储

正式数据库：`会议纪要管理`，MySQL 8，UTF-8（utf8mb4）。网页使用成员账号登录，账号哈希及角色保存在“成员账号”表。应用通过 `.env` 中的 `DATABASE_URL` 使用专属本机账号访问该库，不使用 root 运行。

## 数据表

| 表 | 数据 |
| --- | --- |
| 系统元数据 | 存储版本、初始化标记 |
| 智能模型配置 | AI 开关、地址、模型、API Key |
| 录音转写配置 | 转写地址、转写密钥 |
| 钉钉接入配置 | 群通知和个人通知开关、机器人与企业应用凭证 |
| 成员信息 | 成员姓名、部门、钉钉 UserId |
| 会议记录 | 会议信息、原文、摘要、文件信息与处理状态 |
| 会议发言人 | 会议发言人及成员绑定 |
| 会议任务 | 待审核的会议任务及发布结果 |
| 转写片段 | 录音转写片段与时间位置 |
| 待办事项 | 已发布和手动建立的待办 |
| 通知记录 | 钉钉通知队列、目标校验值、内容和发送结果 |

每个配置或业务实体是独立记录，使用 `编号` 主键、`排序` 顺序、`数据` JSON 保存完整字段；常用姓名、状态、负责人等以生成列提供查询。此方式保留现有数据结构、空字符串及可选字段，避免迁移时截断内容。密钥保存在配置表的服务端 JSON 中，不向网页返回；数据库与备份都应视为含密钥的数据。

录音等二进制文件继续保存在 `data/uploads`，数据库保存其文件名和关联信息。备份时需同时备份数据库、上传目录和 `.env`。

## 启动与迁移

原生部署日常启动：Windows 使用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deploy.ps1 -StartOnly`，Mac 使用 `bash scripts/deploy.sh --start`。启动时直接从 MySQL 读取；连接或写入失败会报错，不会静默回退到 JSON。

首次迁移使用 `npm.cmd run db:migrate`，必须先停止会议服务。迁移会备份源 `data/workspace.json` 到 `data/backups`，创建表后将数据写入同一事务，并重新连接回读校验。数据库已有初始化标记时，不再用旧 JSON 覆盖数据。应用源码不包含实际数据库密码；连接信息在已忽略的 `.env`。

现有 JSON 文件仅是迁移来源，不会跟随新数据库继续更新。不要把旧 JSON 作为迁移后数据的最新备份。

## 写入与校验

保存采用有序事务队列，只写入变动记录；HTTP 成功响应和通知外发都等待必要的数据库提交。数据库写入失败时回滚事务并停止后续操作，修复 MySQL 后重启应用再读取已提交的数据。数据库命名锁防止两个会议服务同时写入。

`npm.cmd test` 执行业务回归。设置 `MYSQL_TEST_ADMIN_URL` 后，还会在独立的随机测试库中验证迁移、API 写入、并发保存、重启读取、单实例锁和事务失败回滚；测试结束删除该测试库，不改正式库，也不真实发送钉钉消息。

## 中文标识迁移

所有物理表名和字段名均使用中文。程序内部对象名称及 JSON 内部键保持兼容，由存储层映射到中文 SQL 标识。旧英文表执行 `npm.cmd run db:chinese` 迁移，需先停止服务并通过 `MYSQL_ADMIN_URL` 提供有 ALTER / DROP / CREATE 权限的账号。脚本先在 data/backups 保存完整表结构与数据，重建只读生成列并重命名，再更新版本标记；重复执行不会重复建表或导入成员。
