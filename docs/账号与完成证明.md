## 给成员分配账号

负责人登录 → 成员管理 → 分配账号/管理账号。填写账号、角色和初始密码，可以重置密码或停用账号。账号为3–40位字母、数字、点、下划线或连字符，不区分大小写；密码8–128字符。

系统管理员管理账号、门店与系统配置；总部负责人管理全部业务；大区负责人、门店负责人分别按账号中指定的大区、门店访问业务数据。普通成员可查看所有已发布会议及其录音，并上传、修改、解析、删除自己上传的未发布会议；发布派单须由负责人审核确认。已发布会议保持不可修改、删除。普通成员可给自己新增待办，并查看自己负责、派发或验收的任务。系统管理员不能停用或降级自己的账号，必须保留至少一个启用的系统管理员。

新建、重置密码后可直接登录，成员可主动修改密码。修改账号、停用或修改密码会使旧会话失效。会话最长8小时，退出登录或重启服务后需要重新登录。账号密码使用随机盐和 scrypt 哈希保存，接口不返回密码哈希。

## 成员完成任务

新派发任务先在详情中接单，再在“任务派发”点击完成复选框，弹窗中可填写完成说明并选一个附件，也可不填写说明、不上传附件直接提交验收。附件单个不超过10MB，支持 PDF、PNG/JPG/WEBP、TXT、Office文档、ZIP。

新派发的任务提交后进入“待验收”，不计入完成率。验收人在任务详情中通过或退回；退回必须填写原因。验收人默认是派单人，发布会议或新增待办时可另选成员。历史未配置验收人的任务保留直接完成方式。

任务详情展示派单、转移、进展、提交、退回、验收的时间轴，以及完成证明。转移任务必须说明原因；待验收、已完成任务不能直接转移。附件仅向有权查看该任务的人员提供下载。

## 数据位置与验证

账号保存到 MySQL“成员账号”中文表；完成历史保存在“待办事项”的“数据”字段；附件文件保存在 `data/completion-files`，文件名由服务端生成，不以用户上传名构造路径。备份时应同时备份数据库和 data 下的录音、完成证明文件。

自动测试覆盖未登录访问、跨成员读写拦截、账号角色、重置密码失效、首次登录直接访问、无附件完成、有附件完成、附件下载权限及 MySQL 持久化。暂未加入附件在线预览和多附件。

负责人手动新增待办后，按已启用的钉钉/飞书群通知和个人通知配置自动创建发送记录。通知失败不回滚已创建待办，可在相应配置页重试。

会议草稿保存、转写和 AI 解析不会发送通知。负责人确认发布后才派单并加入通知队列。提交验收通知验收人；通过或退回通知执行人；转移通知原执行人和新执行人。是否发送群消息、个人消息取决于各平台已启用的配置。

## 会议检索与门店统计

会议转写支持按关键词、大区、门店、门店负责人和日期筛选，默认最近三个自然日。高频问题按规范化后的相同待办标题统计，不进行语义聚类。“待办整理”展示跨门店重复事项；“会议助手”按关键词查询事项状态和会议原文，并提供原文定位。数据看板按登录角色可见范围统计，门店汇总显示该范围内全部历史数据。

## P0 组织、权限与闭环

账号支持系统管理员、总部、部门、大区、门店及普通成员。可单独控制查看、上传、派单、修改、验收、导出能力。部门负责人需填写负责部门；大区和门店负责人需选择负责范围。原有普通成员查看全部已发布会议的规则保留，可在业务规则中切换为本店及本人相关会议。保密会议/问题仅指定人员及系统管理员可访问，任务、原文、附件、查询引用和发送通知均检查限制。

组织人员在“门店组织”管理，业务规则及运维位于“运行管理”，可配置组织上下级、岗位、直属负责人、岗位路由和期限。离职交接转移未完成事项的执行、验收与协作职责，并停用账号、撤销旧登录；历史记录保留原人员。

问题先确认成立，再审核拆分派单；没有匹配负责人时保留待分派。每项任务可设置协作人、必要任务标记及验收人，默认验收人为派单人。执行人接单后处理，可填写退回补充或阻塞原因；交接由接收人确认。所有必要任务通过验收后才能关闭问题，重新打开进入新一轮处理，不用旧任务冒充本轮完成。

会议资料入口可管理主持人、参会人、类型、议题、附件、访问限制、原始转写和修订；决策保留提出、确认、修改及撤回历史。关联历次会议需要提供本次会议的原文依据。

看板根据当前账号权限过滤数据。每日快照在服务运行时每分钟更新当日状态，跨日保留；离线日期不补造历史。日报检查需在业务规则开启。会议助手的 AI 回答使用有权访问的最多60条来源；需要精确问题、成员、门店或日期缩小检索范围，不代表无限量全文搜索。

## 连锁门店组织

系统管理员进入“系统配置 → 门店组织”，通过左侧“大区 → 门店”树查看对应人员。先新增大区，再新增门店，门店可设置店长、地址和营业状态。没有店长时可以先建店，后续再指定。旧成员未关联门店的保留在“待归属”，不会自动划为总部；在人员资料中可明确选择总部及部门。

成员选择门店后大区自动带出；调店不会自动改派其已有任务。大区改名同步所属门店、成员、路由及账号原有大区范围；门店换区同步成员归属。店长和大区负责人属于业务职责，账号可见范围仍单独配置，可兼管多店或多区。

人员“更多”保留钉钉、飞书身份绑定，以及任务/离职交接。账号权限入口可分配账号、修改角色、调整数据范围、停用和重置密码。备份、审计、邮件及业务规则已移入“运行管理”。


## 会议、问题与任务的连续处理

会议审核中的“查看关联问题、决策与处理进度”可进入同一会议的资料、问题和任务。任务详情中的“所属问题 / 关闭进度”可回到问题档案；原文定位支持已有的录音时间点。

会议发布与问题拆分派单共用任务创建逻辑。问题已派单时，发布会议复用已有任务，不重复创建或通知；任务详情提供接单、反馈和验收入口，必要任务全部完成后仍需在问题档案确认解决并关闭。已有派发任务的会议不再允许整体重新解析，原文可修订，失效证据需重新关联确认后才能继续派单。

任务派发页新增“等我接单、等我验收、问题待关闭、资料待确认”队列。历史未完成任务缺少门店或验收人的，由负责人逐项确认；确认资料不会发送通知，也不会补造历史完成或验收。已完成历史任务保留原记录。数据看板增加当前权限范围的流程状态统计，可点击查看任务。


## 跨账号反馈与状态同步

任务派发、数据看板在页面可见且未编辑表单、未打开弹窗时，每20秒同步任务与问题；切回窗口也会同步。新任务进入执行人的待接单队列，提交完成进入指定验收人的待验收队列。派单人也会收到提交、验收、进展和转移事件通知（需已启用对应渠道且成员已绑定平台身份）。

转移任务必须说明原因，新负责人重新接单后才能提交。记录进展不能绕过接单、退回补充或解除阻塞；保密任务不能交给无权访问来源资料的人。停用、离职或缺少相应操作权限的账号不能继续接收新派任务，个人通知发送时也会重新检查账号状态。

从问题档案先派单时，相关任务参与人可查看对应会议原文，即使会议仍待发布；这不会自动授予修改会议权限。无关成员仍不可查看未发布会议。


## 重复提及与例行待办

会议页“重复提及的问题”只统计关联到同一问题档案的多场会议，同一会议只算一次；标题相同不会自动关联。通过问题档案的“关联历次会议”补充原文和跟进信息。问题复发使用“重新打开”，保留原记录和复发次数。

新增、修正问题及审核会议待办时，可选择“问题处理 / 例行待办”。例行待办不进入重复问题统计。历史数据不会仅凭标题猜测性质，请在问题档案中修正。日期与门店展示遵守当前筛选及账号可见范围。

会议审核和新增待办可填写执行日期；同门店、同标题、同执行日期的已派待办提示疑似重复，未填执行日期则采用截止日期（北京时间），日期或门店缺失时不猜测分组。不同日期的任务分别保留。新增待办的重复提醒仅检查当前账号可见任务，确认后仍可独立创建，不自动合并或删除。
