# 钉钉接入：群通知与负责人工作通知

本项目入口：http://127.0.0.1:8765/#dingtalk 。当前只接主动通知，不接收群聊天内容、不做扫码登录。

## 1. 群通知

钉钉客户端 → 目标群 → 群设置 → 群管理 → 机器人 → 添加机器人 → 自定义机器人。

建议使用加签安全设置，记录 Webhook 与 SEC 开头的加签密钥。若配置了关键词，填写与本项目消息关键词一致的词。回到本项目“钉钉通知”，填写群名称、Webhook、加签密钥，启用群通知并保存。

官方文档：
- [创建自定义机器人](https://open.dingtalk.com/document/orgapp/custom-bot-creation-and-installation)
- [获取 Webhook](https://open.dingtalk.com/document/orgapp/obtain-the-webhook-address-of-a-custom-robot)
- [安全设置](https://open.dingtalk.com/document/orgapp/customize-robot-security-settings)
- [发送群消息](https://open.dingtalk.com/document/orgapp/custom-bot-to-send-group-chat-messages)

自定义机器人不能发单聊；个人通知走下一条独立通路。若群管理中没有自定义机器人入口，需企业管理员确认群类型、管理策略和可用能力，不能把群 Webhook 当作个人通知凭证。

## 2. 负责人个人通知

企业管理员或具备相应权限的开发者登录钉钉开发者后台，选择企业并创建/使用企业内部应用。在应用信息/凭证中取得 AppKey、AppSecret、AgentId。确认应用具备发送工作通知权限，接收人在应用可见范围内，并完成所需版本发布。

将三个值填入本项目“负责人通知”，启用并保存。此通路发送企业应用的工作通知，不是个人聊天账号代发。

- [身份与凭证说明](https://open.dingtalk.com/document/orgapp/basic-concepts)
- [权限管理](https://open.dingtalk.com/document/org/permission-management)
- [工作通知接口](https://developer.alibaba.com/docs/api.htm?apiId=37692)

## 3. 成员绑定

企业管理后台 → 通讯录 → 成员管理 → 员工详情，查看 UserId。本项目 → 成员 → 绑定钉钉，填写对应 userid。不要用手机号、姓名或 UnionId 代替。

## 4. 验收

先保存配置，再点发送群测试通知；选择一个已绑定成员，发送个人测试通知。两边都实际收到后，发布一场包含明确负责人的会议任务。群中收到任务汇总，每位负责人只收到自己的任务。

本项目显示“钉钉已受理”不等于最终送达或已读。失败记录可以重试；网络中断等结果不确定的记录，需要核实后手工重发。重启不会盲目重发正在发送的记录。改群或改接收人后不重试旧目标记录。超长内容会明确失败，需拆分会议任务。

## 5. 本地运行边界

只发送消息，本地电脑能访问钉钉接口即可，不需要公网域名或内网穿透；电脑关机时本地服务不会运行。若后续要让成员从消息打开网页，或点击卡片按钮回写任务，需要单独设计可访问地址与回调/鉴权，本次未实现。

## 本轮实现与验证

新增配置、成员绑定、群 HMAC-SHA256 加签、个人工作通知、持久化通知队列、逐负责人消息隔离、幂等防重复、失败/未知状态重试及测试发送。只有新发布且当时开启通知的会议触发发送，历史会议不自动补发；手工新增待办本轮不自动通知。9 组自动化测试使用模拟钉钉响应，实际群/应用凭证尚未提供，未真实发消息。

已逐项打开文档首页的开发场景、基础概念和工具资源卡片；部分入口正文加载不完整，且旧“开发流程”链接落到自定义组件页，所以具体实施以以上已核实正文链接为准。小程序、工作台定制、连接器和互动卡片不是本次主动通知必需项。
