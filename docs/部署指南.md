# Docker Compose 部署

## 准备

安装 Git 和 Docker，启动 Docker Engine/Desktop，使用 Linux 容器及 Compose v2.24+。基础服务建议 2 核 4GB 内存，CPU 转写建议 4 核 8GB 以上并预留数 GB 模型空间。实际用量取决于录音长度。私有仓库需先给部署者的 GitHub 账号访问权限。

运行根目录中的 `scripts/deploy.ps1` 或 `sh scripts/deploy.sh`。无需安装本机 Node、Python、MySQL。脚本生成 `.env.docker`，通过容器启动独立 MySQL、自动建表并创建 `admin` 负责人。不映射宿主 3306，不连接作者的数据库。

首次部署会联网下载镜像、依赖。重复运行保留配置、账号和数据，不重置密码。

## 账号与验收

打开 http://localhost:8765，在自己的终端读取初始密码：

```bash
docker compose --env-file .env.docker exec web cat /app/data/initial-admin.json
docker compose --env-file .env.docker ps
```

首次登录强制改密。改密后文件中的初始密码失效，不能用于找回密码。访问 `/api/health` 应返回 `ok: true`、`storage: mysql`。登录后添加成员和测试待办，重启 web 确认数据仍在，不用真实通知测试部署。

## 局域网访问

修改 `.env.docker`，把示例 IP 换为部署机器的真实 IP：

```dotenv
MEETING_LISTEN_IP=0.0.0.0
MEETING_HTTP_PORT=8765
MEETING_LAN_HOST=192.168.1.100
```

重新运行部署脚本，访问 `http://实际IP:8765`。Host 配置只填 IP 或域名，不填协议/端口。防火墙应放行对应端口，优先限制为局域网。公网部署另需 HTTPS 反向代理，保留 Host/Origin，并支持 60MB 上传和最长 30 分钟解析请求；域名与云防火墙不自动配置。

## 录音转写（可选）

```bash
docker compose --env-file .env.docker --profile speech up -d --build funasr
docker compose --env-file .env.docker logs --tail 60 funasr
docker compose --env-file .env.docker exec funasr python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:10097/health').read().decode())"
```

首次启动从 ModelScope 下载模型，等待健康检查成功再使用录音。模型保存在独立卷。智能配置中转写地址填 `http://funasr:10097/v1`，不要填 localhost（它代表网页容器自己）。转写端口不对宿主开放。基础网页无需等待模型即可处理文字稿。

AI 默认关闭，需填写兼容 Chat Completions 的服务地址、模型和密钥。钉钉、飞书默认不发送通知，需配置各自的应用、权限和成员绑定。

## 更新、停机与备份

```bash
git pull --ff-only
docker compose --env-file .env.docker up -d --build --wait db web
# 停止服务，保留数据
docker compose --env-file .env.docker --profile speech down
```

保留同一 Compose 项目名和 `.env.docker`，已有数据库不要重新生成密码。日常操作不要加 `down -v`，它会删除数据卷。启用了转写时按上面的 speech 命令更新其镜像。

备份需同时保存 MySQL 数据和 meeting-data 附件卷，以及 `.env.docker`。先停止 web，使用数据库容器中的 mysqldump 导出到容器文件，再用 `docker compose cp` 复制出来，避免 Windows 重定向改变 SQL 编码。附件使用 `docker compose cp web:/app/data backups/app-data`。备份完启动 web。数据库备份包含接入密钥，应私密保存。恢复必须先停止 web，在独立环境验证后恢复 SQL 和附件，保持 node 用户读写权限；不要向现有业务库盲目导入。

## 排错

- daemon 未运行：启动 Docker Desktop，确认 `docker info` 成功。
- 镜像下载失败：检查 Docker Hub、npm 和代理网络后重试，不使用来源不明的镜像。
- 端口占用：更改 MEETING_HTTP_PORT 并重启。
- HTTP 403：核对 MEETING_LAN_HOST 与访问 IP/域名。
- MySQL 密码错误：恢复与已有数据卷对应的原 `.env.docker`，不要删库。
- unhealthy：运行 `docker compose --env-file .env.docker logs --tail 100 web db`；分享日志前隐藏密钥。

参考：[Docker 官方健康检查与启动顺序](https://docs.docker.com/compose/how-tos/startup-order/)。
