# 原生部署指南

## 首次部署

Windows 10/11 x64 使用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deploy.ps1`；Mac 使用 `bash scripts/deploy.sh`。命令在项目根目录运行，不需要 Docker。请先阅读 README.md 的环境和空间要求。

脚本自动准备 Node.js 22+、Python 3.12、MySQL 8.0/8.4、FFmpeg、FunASR 和全部四组模型。Windows 自动下载缺失的 Node/MySQL，通过 winget 安装缺失的 Python 和运行库；Mac 使用 Homebrew。系统安装需要授权时按终端提示操作。

新用户不要先复制 `.env.example`。脚本自动创建 `.env`、独立的 `.runtime/native-mysql` 数据目录和随机数据库密码。默认 MySQL 端口 13306，仅本机可访问，不占用已安装 MySQL 的 3306，不连接原作者数据库。中文数据库名为“会议纪要管理”，业务表和字段使用中文。

首次安装联网下载依赖和模型，耗时取决于网络。失败时明确停止；修复网络后重新运行，不要删除数据目录。四组模型实际加载成功后，脚本才继续完成启动验收。

## 启动与验收

下次 Windows 添加 `-StartOnly`，Mac 添加 `--start`。无需重复下载。网页默认 http://127.0.0.1:8765 。保持终端运行，Ctrl+C 会停止本次启动的服务；已存在并复用的转写服务不会被关闭。

新部署账号为 admin，Windows 用 `Get-Content data/initial-admin.json`、Mac 用 `cat data/initial-admin.json` 读取随机密码。首次登录强制修改，改密后原密码失效，不能靠此文件找回。已部署用户继续使用原账号。

验收 `/api/health` 返回 `ok: true`、`storage: mysql`，`http://127.0.0.1:10097/health` 返回 `model_loaded: true`。确认登录页正常、可新增测试待办，停止后再次启动确认任务仍在。不要用真实群通知验证安装。

智能配置的转写地址为 `http://127.0.0.1:10097/v1`。AI 默认关闭，需填写自己的模型、地址和密钥；钉钉、飞书需自行开通应用权限、发布应用和绑定成员。

## 已有部署与更新

已有 `.env` 时连接原数据库，不替换账号、密码或业务数据。原数据库服务需要保持运行；脚本会检查数据库是否可用。旧 Docker 数据不会自动迁移成原生数据库，已有容器用户应先备份并制定迁移方案。

先 Ctrl+C 停止本项目，备份后 `git pull --ff-only`，再运行完整部署命令安装依赖并重建网页。无需手动重建数据库。不要在不同版本 MySQL 之间直接复用数据目录或修改凭据文件。

## 局域网访问

在 `.env` 设置：

```dotenv
MEETING_BIND_HOST=0.0.0.0
MEETING_LAN_HOST=192.168.1.100
```

将 IP 换成本机实际 IP，重启并在防火墙允许局域网访问网页端口。其他电脑访问 `http://实际IP:8765`。数据库和语音服务仍仅本机访问。公网使用还需配置 HTTPS 和反向代理。

## 文件与备份

- `.env`：网页和数据库连接配置。
- `.runtime/native-tools.json`：已安装程序路径。
- `.runtime/native-mysql/`：新部署数据库、随机凭据和初始化标记。
- `.runtime/models/`：四组模型缓存。
- `data/`：完成证明等附件及初始管理员信息。
- `logs/native-*.log`：服务日志。

先停止本项目并确认 MySQL 已结束，再一起备份 `.env`、`data` 和 `.runtime/native-mysql`。数据目录备份仅适用于同平台、兼容的 MySQL 版本；跨平台迁移使用 mysqldump 逻辑导出再导入。使用原有外部 MySQL 的用户应单独备份那个数据库。备份含应用密钥和个人数据，请私密保存，不能上传 GitHub。

## 排错

- 端口占用：停止旧服务；新部署前可以设置 PORT、FUNASR_PORT、MYSQL_LOCAL_PORT 环境变量。已有原生数据库的 MYSQL_LOCAL_PORT 不可随意更改。
- 下载失败：检查 npm、PyPI、PyTorch、ModelScope、Node/MySQL 官方下载站及 Homebrew 网络。
- 缺少系统组件：按终端提示安装 winget、VC++ 运行库或 Mac 开发工具后重试。
- 模型未就绪：查看 `logs/native-funasr.log`，确认内存、磁盘和模型下载完整，再运行完整部署命令。
- 数据库启动失败：查看 `logs/native-mysql.log`。禁止通过删除数据、凭据或 secured 标记排错。
- 网页启动失败：查看 `logs/native-web.log`，核对 `.env`。分享日志前隐藏密钥。
- HTTP 403：核对访问地址与 MEETING_LAN_HOST。

仓库的原生数据库集成测试使用独立临时数据目录，不访问业务数据库。CI 在 Windows/macOS 验证构建、应用测试和原生 MySQL 初始化、登录、重启持久化；语音模型另有实际加载检查。请区分检查覆盖范围与全新机器完整安装验收。
