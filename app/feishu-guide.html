使用说明

从创建机器人到发送成功：群通知与负责人通知的完整配置步骤。

配置顺序：创建应用 → 添加机器人能力 → 开通权限并发布 → 添加机器人进群 → 获取并绑定员工 open_id → 保存配置并测试。

1. 创建应用后，还要添加机器人能力

  1. 进入飞书开发者后台，打开已创建的“会议纪要”企业自建应用。
  2. 在“添加应用能力”中选择“机器人 → 添加”。不需要重新创建应用，App ID 和 App Secret 沿用原来的。
  3. 按后台提供的选项设置名称、头像和简介，机器人可命名为“待办提醒”。

如果已经能看到“机器人配置、消息卡片回调请求方式、机器人自定义菜单”等内容，就继续检查权限和发布状态。

2. 开通权限，并发布应用

用途权限与范围
发送群通知和个人通知im:message:send_as_bot（以应用的身份发消息），选择应用身份权限
通过手机号或邮箱查询员工 open_idcontact:user.id:readonly（通过手机号或邮箱获取用户 ID），通讯录权限范围须包含目标员工
通过接口查询群信息或群列表按对应接口要求开通群读取权限，例如 im:chat:read；群读取权限与发消息权限不同

在“版本管理与发布”创建并发布版本，按企业要求完成管理员审批。修改机器人能力或权限后，要确认变更已生效。个人通知还要求接收人在应用可用范围内。

不是必须由管理员亲自查询 open_id：有权限的应用开发者也可通过接口查询；权限审批和通讯录数据范围可能需要企业管理员设置。

3. 将应用机器人添加到会议群

  1. 在飞书中打开目标会议群，进入“群设置 → 群机器人 → 添加机器人”。
  2. 搜索并添加当前应用对应的机器人。核对所属应用，避免添加同名机器人或自定义 Webhook 机器人。
  3. 在开放平台 API 调试台使用本应用的 tenant_access_token 调用“获取用户或机器人所在的群列表”，按接口要求开通权限，查找目标群的 chat_id。
  4. 回到“飞书配置 → 接入配置”，填写群名称及 oc_ 开头的 chat_id，勾选群通知并保存。

群名称只是本地备注，真正决定接收群的是 chat_id。不能填写群邀请链接或 Webhook。机器人已入群但仍报错时，核对 App ID 和 chat_id 是否对应这个机器人、这个群。

4. 获取员工 open_id：Token 和手机号分别填在哪里

打开通过手机号或邮箱获取用户 ID文档，进入 API 调试台。

  1. 请求头 Authorization：点击“获取 Token”，选择与本地 App ID 一致的应用，获取并使用 tenant_access_token。这里填令牌，不能填手机号、员工编号或 App Secret。
  2. 查询参数 user_id_type：选择 open_id。
  3. 请求体：删除默认示例邮箱和手机号，替换为以下 JSON，并将占位文字换成目标员工在飞书企业通讯录中登记的真实手机号。
{
  "mobiles": ["替换为员工在飞书登记的真实手机号"],
  "include_resigned": false
}

也可以通过邮箱查询，使用下面的请求体，将占位文字替换成通讯录中登记的真实邮箱。两种方式选一种即可。

{
  "emails": ["替换为员工在飞书登记的真实邮箱"],
  "include_resigned": false
}
  1. 点击“开始调试”，查看 data.user_list 中是否出现 user_id。
  2. 当查询参数选择了 open_id 时，返回字段虽然叫 user_id，里面的 ou_… 就是需要绑定的 open_id。下面只展示返回结果中的单个用户示例：
{
  "user_id": "ou_示例编号",
  "mobile": "员工手机号"
}

HTTP 200 / code 0 只代表调用成功，不代表查到了员工。如果只返回 mobile 或 email，没有 user_id，请检查：是否仍在使用默认示例数据、手机号或邮箱是否与企业通讯录一致、通讯录权限范围是否包含该员工。

5. 绑定负责人并测试

  1. 在本地“飞书配置 → 接入配置”保存 App ID 和 App Secret。密钥留空表示保留，更换 App ID 时需重新填写密钥。
  2. 打开“成员管理 → 对应成员 → 绑定飞书”，粘贴刚查询到的完整 ou_… 编号并保存。
  3. 回到飞书接入配置，启用“单独通知每位任务负责人”，保存后选择该成员，点击“发送个人测试通知”。群通知也需先启用并保存，再点击群测试按钮。

钉钉 userid 不能用于飞书，同一员工在不同飞书应用中的 open_id 也不能混用。更换应用后需要重新查询、绑定。不要把文档中的“ou_示例编号”当作真实编号。

6. 常见报错与处理

报错或现象处理方法
负责人未绑定飞书 open_id到“成员管理 → 对应成员 → 绑定飞书”填写本应用获取的 open_id，保存后再重试。
99991672：权限不足按报错所列权限开通所需权限。发送消息时列出的 im:message:send、im:message、im:message:send_as_bot 是备选权限，建议只开通 im:message:send_as_bot，并发布变更。群读取接口报错则需对应的群读取权限。
230002：机器人不在目标群把当前 App ID 对应的应用机器人加入目标群，并核对 chat_id。仅创建应用或启用机器人能力，还没有完成入群。
99991668 / user access token not support检查 Authorization 中使用的令牌类型。点击“获取 Token”，获取本应用的 tenant_access_token；不要使用 user_access_token，更不能填写手机号。
调用成功，但没有 user_id换掉默认示例手机号和邮箱；核对真实通讯录信息及应用的通讯录权限范围。
HTTP 400结合具体错误码和失败阶段排查。单凭 HTTP 400 无法判断是凭证、权限、接收编号还是入群问题。
应用或接收目标已改变，无法重试保存正确配置后，点击“发送群测试通知”或“发送个人测试通知”创建新测试，不要继续重试指向旧目标的记录。
结果不确定先到飞书检查是否已经收到，确认未收到后再手动重发，避免重复通知。

7. 正式使用与当前功能范围

上传录音或纪要 → 转写与 AI 解析 → 审核任务、选择负责人 → 发布会议。启用的渠道会通知新发布的会议，群收到全部任务，负责人只收到自己的任务；不会自动补发历史会议。测试按钮会真实发送消息，“已受理”不代表员工已读。

发送通知只需本机服务运行并能联网，不需要公网回调。当前支持文字通知、发送记录和失败重试；暂未接入接收消息、交互卡片按钮、飞书原生任务同步和自动到期提醒。本地 127.0.0.1 网页地址不能供其他员工访问。
